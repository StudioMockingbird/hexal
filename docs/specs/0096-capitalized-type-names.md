# RFC 0096: Capitalized Type Names

- Kind: Feature Specification (Rust-Style RFC)
- Status: Draft; implementation-ready
- Created: 2026-08-20
- Scope: require an uppercase initial on Hexal type names, and capitalize the
  `Hex` prefix on every generated C identifier that names a type
- Depends on: nothing. Independent of RFC 0095, which fixes two name
  collisions; this one changes case and nothing else
- Coordinates with: the checker, the generator, the runtime templates,
  `docs/reference.md`, `AGENTS.md`, the workbench catalog, the snippet manifest
- Does not change: type identity, name resolution, generated structure, or any
  semantics. A program that compiles today compiles after, unless it declares a
  lowercase type name

## Summary

Types read differently from values when their case says so. Hexal adopts the
convention on both sides of the compiler:

```hexal
type Meter = { reading: Int32, }        -- required
type meter = { reading: Int32, }        -- rejected
```

```c
Hex_t_m3_app_Meter hex_v_live = ...;    -- type capitalized, binding not
Hex_list_Int32 *hex_v_names = ...;
```

The C half is the point: a reader scanning generated output can tell a type
from a value at a glance, which is exactly what `hex_t_m3_app_Meter hex_v_live`
does not offer today. The Hexal half makes the convention the language's rather
than the code generator's, and it is what lets the C half be a pure case
mapping rather than a transformation.

## Part A — Hexal source

A declared type name must begin with an uppercase letter `A`-`Z`. This covers:

- `type` declarations, whether alias, object, or ADT;
- ADT variant names;
- generic type parameters.

Diagnostic, at the name token:

> `type names must begin with an uppercase letter`

Everything else is unchanged. Bindings, parameters, members, functions, and
methods keep their existing rules and may start with any letter. A lowercase
*binding* named `meter` beside a type `Meter` stays legal and unambiguous, and
the existing type/value collision rules are untouched.

**The migration is one line.** Grepping every Hexal source in the repository —
the workbench catalog, every integration-test source string, and
`docs/reference.md` — finds exactly one lowercase type declaration, and it is a
deliberate negative case:

```go
// aliases_test.go, TestRejectsTypeValueCollisions
"distance: Int32 := 1 type distance = Int32",
```

It asserts a value and a type cannot share a name. Rewriting it as
`Distance: Int32 := 1 type Distance = Int32` preserves what it tests, because
the collision rule is case-sensitive and independent of this one.

## Part B — Generated C

Every generated identifier that names a **type** takes the prefix `Hex_`.
Everything else keeps `hex_`.

| Names a type — `Hex_` | Does not — `hex_` |
|---|---|
| `Hex_t_<owner>_<Name>` objects and ADTs | `hex_v_` bindings |
| `Hex_list_`, `Hex_array_`, `Hex_view_`, `Hex_dict_` | `hex_f_` functions and methods |
| union types and their `_tag` enum typedefs | `hex_m_` object members |
| `Hex_string`, `Hex_strand`, `Hex_heap`, `Hex_task`, `Hex_chan`, `Hex_mutex_control`, `Hex_rune_cursor`, `Hex_eos` | `hex_for_N`, `hex_try_N`, `hex_lit_N`, `hex_match_scrutinee_N` and every other generated local |
| `Hex_heap_header`, `Hex_string_storage`, `Hex_guard_range`, `Hex_context_impl` | every runtime function, e.g. `hex_string_from_bytes` |

**Enum constants and payload fields capitalize with their type**, not against
it: an ADT tag is `Hex_t_m3_app_Shape_Circle` and its payload field stays
`.payload.Circle`. They are spelled from the type's name, and splitting the
case mid-identifier — `hex_t_m3_app_Shape_Circle` beside type
`Hex_t_m3_app_Shape` — would differ by one letter in a way no reader would
trust.

`HEX_` remains reserved for generated macros and is unaffected: C is
case-sensitive, so `HEX_MODULE_m3_app_H` and `Hex_string` are distinct
identifiers. They are one keystroke apart in source, which is a real
readability cost and the main argument against this RFC.

**The template inventory is closed.** The hand-written runtime templates define
twelve type names, listed above; the rest are generated by the six family
builders. There is no third source.

## Invariants

1. Case only. No identifier gains, loses, or reorders any other character.
2. Generated structure, layout, ordering, and includes are unchanged.
3. No program's acceptance changes except one that declares a lowercase type
   name, which is now rejected.
4. `HEX_` macro names are untouched.
5. C is case-sensitive, so the rename is total: no generated identifier keeps a
   lowercase `hex_` prefix while naming a type, and none gains `Hex_` while
   naming a value.

## Validation

This section is exhaustive.

- `type meter = { reading: Int32, }` is rejected with the exact diagnostic at
  the name token; `type Meter` is accepted.
- A lowercase ADT variant name and a lowercase generic parameter are each
  rejected with the same diagnostic.
- A lowercase *binding*, parameter, member, function, and method each remain
  accepted, including a binding whose name differs from a type only by case.
- The type/value collision diagnostics are unchanged, verified by the rewritten
  `TestRejectsTypeValueCollisions` cases.
- A program using an object, an ADT, a union, and one specialization of each of
  List, View, Array, and Dict generates `Hex_`-prefixed names for all of them
  and `hex_`-prefixed names for every binding, function, member, and generated
  local in the same output.
- Each of the twelve template type names appears capitalized, and no
  `typedef struct hex_` or `typedef union hex_` or `typedef enum hex_` survives
  anywhere in generated output.
- An ADT tag constant is `Hex_t_<owner>_<Name>_<Variant>` and its payload field
  is `.payload.<Variant>`.
- No generated function name is capitalized: `hex_string_from_bytes` and every
  other runtime entry point keeps its prefix.
- Include guards keep the `HEX_MODULE_` form.
- The snippet manifest moves for every snippet, since every program names at
  least one type. No snippet's output changes other than by case.
- `docs/reference.md` records the source rule and the updated naming table.
  `AGENTS.md`'s naming guidance follows.
- `go test ./...`, `go vet ./...`.

## Non-goals

- Renaming `hex_` to anything else, or changing the `HEX_` macro reservation.
- Requiring or forbidding a case convention on bindings, functions, members, or
  module aliases.
- Changing `Byte`, `Rune`, or any builtin spelling. All builtin type names are
  already capitalized.
- Fixing the name collisions in RFC 0095. This RFC changes case; that one
  changes which characters are there. They touch the same identifiers and
  should land in either order, with the second rebaselining the manifest.

## Drawbacks

- `Hex_` and `HEX_` differ by one keystroke and now both appear in generated
  output. The mitigation is that `HEX_` occurs only in include guards, which
  sit at the top of a file and nowhere else.
- Every snippet's manifest entry moves, for a change that alters no behaviour.
  This is the widest manifest movement of any open spec.
- A capitalized prefix on a lowercase family stem reads oddly at first:
  `Hex_list_Int32`, not `Hex_List_Int32`. Capitalizing the stem too would
  require deciding the case of every runtime type name individually, and the
  family stems are structure rather than names.
